1. 프롬프트보다 비트시트 먼저

9개 비트짜리 한 장 시트가 9개 샷에 그대로 대응합니다. 각 비트에는 누가 무엇을 원하는지, 무엇이 막는지, 샷이 어떻게 끝나는지를 적습니다. 한 문장으로 설명되지 않는 비트는 이미 두 개의 비트입니다. 이 단계를 건너뛰면 생성 모델이 아무리 좋아도 편집에서 무너집니다.

2. 샷 리스트와 길이

생성 샷은 3~6초로 유지하세요. 그보다 길면 얼굴이 바뀌고 손이 붙고 카메라 무브가 의도를 잃습니다. 크로스페이드보다 움직임 위에서 컷을 끊는 편이 이음새를 훨씬 잘 숨깁니다. 샷마다 샷 ID, 프롬프트, 시드, 참조 이미지를 한 줄로 남겨 두면 재촬영이 추측이 아니라 조회가 됩니다.

3. 일관성은 결국 이미지 문제

텍스트→영상은 설정 샷, 날씨, 군중, 삽입 컷에 적합합니다. 반복 등장하는 인물은 캐릭터 시트를 먼저 만들고, 그 참조 이미지로 이미지→영상을 돌리는 편이 안정적입니다. 의상과 헤어처럼 자주 흔들리는 요소는 참조 이미지에 고정해 두세요. 같은 인물을 세 번 생성해 보고 가장 나은 테이크를 기준으로 삼는 방식이 현실적입니다.

4. 보이스, 음악, 자막

순서는 화면 → 보이스 → 음악입니다. 화면이 잠기기 전에 보이스를 넣으면 컷 길이를 계속 고치게 됩니다. 세로 영상 자막은 두 줄 이내, 한 줄 20자 안팎이 읽기 좋고, 플랫폼 UI 위쪽에 배치합니다. 번인 자막은 재업로드에서도 살아남지만 사이드카 파일은 대개 사라집니다.

5. 납품 체크리스트

  • 첫 1.5초 안에 훅이 보이는가
  • 9:16 마스터와 유튜브용 16:9 컷이 따로 있는가
  • 라우드니스는 소셜 -14 LUFS, 웹 -16 LUFS 근처인가
  • 파일명, 캡션, 썸네일을 업로드 전에 써 두었는가
